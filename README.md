# AESCRYPT

AESCRYPT is an educational AES encryption platform built to make AES encryption easier to understand through interactive encryption, decryption, comparison, and block-level visualization.

The project combines a React-based frontend with a Flask backend to demonstrate how AES works with different modes, particularly ECB and CBC.

---

## Features

- AES file encryption
- AES file decryption
- Text encryption and decryption
- ECB mode support
- CBC mode support
- Block-by-block AES visualization
- Plaintext, AES input, and ciphertext inspection
- ECB vs CBC comparison
- Detection of repeated ciphertext blocks
- PKCS#7 padding visualization
- Ciphertext copying
- Interactive encryption/decryption interface

## How It Works

AESCRYPT provides three main ways to interact with AES:

### 1. File Encryption

Users can select a file and encrypt it using AES.

The encrypted file is generated by the Flask backend and returned to the frontend for download.

### 2. AES Visualization

The visualization interface allows users to enter text and observe how the plaintext is divided into AES blocks.

The interface displays:

```text
Plaintext
    ↓
AES Input
    ↓
AES Encryption
    ↓
Ciphertext
```

Individual blocks can be inspected to understand how the data changes during encryption.

### 3. ECB vs CBC Comparison

The comparison interface encrypts the same plaintext using both ECB and CBC modes.

This makes it possible to observe how the two modes handle repeated plaintext blocks.

For example:

```text
Plaintext

BLOCK 1 = ATTACK AT DAWN!!
BLOCK 2 = ATTACK AT DAWN!!
```

With ECB, identical plaintext blocks can produce identical ciphertext blocks.

CBC combines each plaintext block with the previous ciphertext block before encryption, resulting in different ciphertext blocks for repeated plaintext blocks when a proper IV is used.

---

## AES Modes

### ECB

Electronic Codebook (ECB) encrypts each plaintext block independently.

```text
P1 → AES → C1
P2 → AES → C2
P3 → AES → C3
```

Because blocks are processed independently:

```text
P1 = P3

        ↓

C1 = C3
```

This makes repeated patterns visible in the ciphertext.

---

### CBC

Cipher Block Chaining (CBC) combines each plaintext block with the previous ciphertext block before encryption.

```text
P1 ⊕ IV → AES → C1

P2 ⊕ C1 → AES → C2

P3 ⊕ C2 → AES → C3
```

This means identical plaintext blocks can produce different ciphertext blocks.

---

## Padding

AES operates on fixed-size 128-bit blocks.

When the plaintext does not completely fill the final block, padding is added before encryption.

AESCRYPT uses PKCS#7 padding.

When the plaintext length is already exactly a multiple of the AES block size, PKCS#7 adds a complete padding block.

The visualization interface displays this padding block separately to make the process easier to understand.

## Backend API

The Flask backend provides endpoints for file and text encryption/decryption.

### File Encryption

```text
POST /api/encrypt
```

Encrypts an uploaded file using the selected AES mode.

### File Decryption

```text
POST /api/decrypt
```

Decrypts an encrypted file.

### Text Encryption

```text
POST /api/text/encrypt
```

Encrypts text and returns block-level information used by the visualization and comparison interfaces.

### Text Decryption

```text
POST /api/text/decrypt
```

Decrypts encrypted text.

## Running the Project Locally

### Backend

Navigate to the backend directory:

```bash
cd backend
```

Create a Python virtual environment:

```bash
python -m venv venv
```

Activate the virtual environment.

#### Windows

```bash
venv\Scripts\activate
```

Install the required packages:

```bash
pip install -r requirements.txt
```

Start the Flask server:

```bash
python app.py
```

The backend runs locally on:

```text
http://127.0.0.1:5000
```

---

### Frontend

Open another terminal and navigate to the frontend:

```bash
cd frontend
```

Install dependencies:

```bash
npm install
```

Start the Vite development server:

```bash
npm run dev
```

Vite will provide the local frontend URL in the terminal.

## Development Notes

The project currently uses development/demo cryptographic values for the educational workflow.

These values are intended for demonstration purposes and **must not be used for protecting real sensitive data**.

AESCRYPT is an educational project designed to demonstrate AES concepts rather than serve as a production-grade encryption system.

---

## Purpose

AESCRYPT was created to bridge the gap between learning AES theoretically and understanding what happens to data during actual encryption.

Instead of treating encryption as a black box, the project provides an interactive way to observe:

- Plaintext blocks
- AES input
- Ciphertext blocks
- Repeated blocks
- ECB behavior
- CBC behavior
- Padding
- Encryption and decryption
